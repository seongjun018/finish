# QA 재현 절차

## 공통 상태

| 상황 | 재현 | 기대 결과 |
| --- | --- | --- |
| 정상 | 정상 버튼 | 현재 기능의 가상 데이터 표시 |
| 로딩 | 로딩 버튼 | 로딩 안내·스켈레톤 유지, 정상 복원 가능 |
| 빈 데이터 | 빈 데이터 버튼 | 0건 안내, 오류로 오인시키지 않음 |
| 오류 | 오류 버튼 | 오류 안내·코드·재시도, 이전 데이터 제거 |
| 강제 오프라인 | 오프라인 버튼 | 연결 안내, 재시도해도 강제 상태 유지 |
| 실제 오프라인 | 브라우저 네트워크 끄기 | offline 감지, 성공 데이터 제거 |
| 연결 복구 | 네트워크 켜기 | 강제 오프라인이 아닌 경우 자동 재조회 |
| 실제 API 미연결 | Mock Data 끄기 | LIVE_NOT_CONFIGURED, 가상 데이터로 대체하지 않음 |
| 초기화 | 리허설 초기화 | 현재 기능 유지, 정상 Mock, 재시도 0 |
| 공유 URL | 시나리오 선택 후 링크 복사 | 새로 열어도 같은 기능/시나리오 재현 |
| 빠른 기능 변경 | 요청 도중 다른 메뉴 | 마지막 선택 기능 데이터만 표시 |

## 기능별 예외 시나리오

| 기능 | 시나리오 | 코드 | 다시 시도 |
| --- | --- | --- | --- |
| 대시보드 | 현황 조회 지연 | REQUEST_TIMEOUT | 두 번째 요청 성공 |
| QR 체크인 | 중복 입장 | ALREADY_CHECKED_IN | 표시하지 않음 |
| QR 체크인 | 잘못된 QR | INVALID_QR | 표시하지 않음 |
| 청중평가 | 투표 마감 | VOTING_CLOSED | 표시하지 않음 |
| 청중평가 | 중복 투표 | ALREADY_VOTED | 표시하지 않음 |
| 심사위원 평가 | 저장 실패 | SAVE_FAILED | 두 번째 요청 성공 |
| 점수 집계 | 미제출 심사 | SCORES_INCOMPLETE | 표시하지 않음 |
| 경품 추첨 | 대상자 없음 | NO_ELIGIBLE_PARTICIPANTS | 표시하지 않음 |
| 결과 내보내기 | 파일 생성 실패 | EXPORT_FAILED | 두 번째 요청 성공 |
| 행사·팀 관리 | 저장 실패 | EVENT_SAVE_FAILED | 두 번째 요청 성공 |
| 인증·권한 | 세션 만료 | SESSION_EXPIRED | 표시하지 않음 |
| 인증·권한 | 권한 없음 | FORBIDDEN | 표시하지 않음 |

## 검증 범위 주의

실제 QR/투표/심사/추첨/파일 생성 기능을 테스트한 결과가 아닙니다. 이 모듈의 상태 재현, fixture 서비스, UI 전환, 취소 및 복구 동작을 검증합니다. 실제 운영 시나리오는 팀 기능과 API 연결 후 다시 검증해야 합니다.

## 실행 결과

2026-10-13 로컬 실행 결과:

| 명령 | 결과 |
| --- | --- |
| `npm install` | 성공, lockfile 생성 |
| `npm run typecheck` | 통과 |
| `npm test` | 30개 통과 |
| `npm run build` | 통과, `/` 및 `/admin/qa` 정적 생성 |
| `npm run test:e2e` | 환경 차단: Chromium 시작 시 `socket() failed: Operation not permitted` |

브라우저 테스트는 앱 실행 이전에 환경 제한으로 차단되었으며 통과로 간주하지 않습니다. 화면 캡처와 육안 검토도 로컬에서는 미실행입니다. GitHub Actions는 브라우저를 설치한 후 동일한 시나리오를 실행하고, `playwright-results` 아티팩트에 정상/오류 화면 캡처를 보관하도록 구성했습니다. Actions 결과는 별도로 확인해야 합니다.
